## Общие настройки

**Путь:** Админ-панель → Система → Настройки  
**Требуемое право:** `settings_general`

### Основные параметры

```
Название портала
├── Отображается в шапке сайта
├── Используется в email уведомлениях
└── Рекомендуется: краткое название компании

Описание
├── Краткое описание портала
└── Используется в meta-тегах

Язык интерфейса
├── Русский (по умолчанию)
└── Английский (в разработке)

Часовой пояс
├── Для корректного отображения времени
└── Например: Europe/Moscow
```

### Настройки безопасности

```
Минимальная длина пароля
├── По умолчанию: 8 символов
└── Рекомендуется: 12+ символов

Требовать сложный пароль
├── Да - буквы, цифры, спецсимволы
└── Нет - любые символы

Время сессии (минуты)
├── Автоматический выход при неактивности
└── По умолчанию: 480 (8 часов)

Максимум попыток входа
├── Блокировка после N неудачных попыток
└── По умолчанию: 5 попыток
```

### Настройки уведомлений

```
Включить email уведомления
├── Да - отправка уведомлений на почту
└── Нет - только внутренние уведомления

Включить push уведомления
├── Да - браузерные уведомления
└── Нет - отключены

Частота дайджеста
├── Ежедневно
├── Еженедельно
└── Отключен
```

## Настройка меню

**Путь:** Админ-панель → Система → Меню  
**Требуемое право:** `settings_menu`

### Обзор

Настройка пунктов меню в шапке портала для пользователей.

### Ограничения

- Максимум 4 пункта в основном меню
- Остальные пункты попадают в выпадающий список "Ещё"
- Порядок можно изменять перетаскиванием

### Доступные пункты

```
Главная (main)
├── Главная страница портала
└── Рекомендуется: всегда видимый

Новости (news)
├── Лента новостей компании
└── Рекомендуется: всегда видимый

Сотрудники (staff)
├── Справочник сотрудников
└── Популярный раздел

Вакансии (vacancies)
├── Открытые вакансии
└── Для компаний с активным наймом

Отпуска (vacations)
├── Планер отпусков
└── Важный раздел для всех

Заявки (requests)
├── Подача заявок (пропуска, заказы)
└── Зависит от процессов компании

Опросы (surveys)
├── Активные опросы
└── Если часто проводятся

Тесты (tests)
├── Обучающие тесты
└── Для компаний с обучением

Безопасность (security)
├── Центр безопасности
└── Важная информация

Мессенджер (messenger)
├── Внутренний чат
└── Если активно используется

Таблицы (tables)
├── Совместные таблицы
└── Для совместной работы
```

### Настройка

1. **Выбор видимых пунктов**
   - Отметьте чекбоксы у нужных пунктов
   - Максимум 4 пункта
   - При превышении появится предупреждение

2. **Изменение порядка**
   - Наведите на иконку ⋮⋮ справа от пункта
   - Зажмите и перетащите на нужное место
   - Порядок сохраняется автоматически

3. **Сохранение**
   - Нажмите **"Сохранить"**
   - Изменения применяются немедленно
   - Все пользователи увидят новое меню

### Рекомендации

**Обязательные пункты:**
- Главная
- Новости
- Сотрудники

**Дополнительно (выберите 1):**
- Отпуска - если активно используется
- Вакансии - если часто нанимаете
- Мессенджер - если основной канал связи

**В меню "Ещё":**
- Редко используемые разделы
- Специализированные функции
- Дополнительные сервисы

## Настройки отпусков

**Путь:** Админ-панель → Система → Отпуска  
**Требуемое право:** `vacations`

### Обзор

Настройка лимитов и типов отпусков для всех сотрудников компании.

### Ежегодный оплачиваемый отпуск

```
Количество дней в год
├── По умолчанию: 28 дней (стандарт РФ)
├── Можно изменить: 0-365
└── Применяется ко всем новым сотрудникам

Как работает:
├── Каждому сотруднику доступно N дней в год
├── При одобрении заявки дни вычитаются
├── При исчерпании лимита тип блокируется
└── Отображается серым с надписью "(дни закончились)"
```

**Настройка:**
1. Введите количество дней (например, 28)
2. Нажмите **"Сохранить настройки"**
3. Изменения применяются к новым балансам

**Важно:**
- Существующие балансы не изменяются автоматически
- Для изменения существующих балансов используйте SQL
- Рекомендуется менять в начале года

### Day Off

```
Включить Day Off
├── Переключатель вкл/выкл
└── При включении появляется в списке типов отпуска

Количество дней Day Off в год
├── Настраиваемое значение: 0-365
├── Применяется ко всем сотрудникам
└── Отдельный лимит от ежегодного отпуска

Как работает:
├── Day Off - дополнительные выходные дни
├── Отдельный учет от ежегодного отпуска
├── Те же правила согласования
└── Вычитание дней при одобрении
```

**Настройка:**
1. Включите переключатель "Day Off"
2. Введите количество дней (например, 5)
3. Нажмите **"Сохранить настройки"**
4. Day Off появится в форме заявки

**Отключение:**
1. Выключите переключатель
2. Day Off исчезнет из списка типов
3. Существующие заявки сохраняются
4. Баланс Day Off не обнуляется

### Логика работы системы

#### 1. Создание заявки

```
Проверка доступных дней:
├── Одобренные заявки (вычтены из баланса)
├── + Ожидающие заявки (pending_manager, pending_hr)
├── + Запрашиваемые дни
└── = Должно быть ≤ Лимита

Если дней недостаточно:
├── Заявка блокируется
├── Показывается сообщение с доступным балансом
└── Тип отпуска отображается серым
```

**Пример:**
```
Лимит: 28 дней
Одобрено: 10 дней
Ожидают: 15 дней
Доступно: 28 - 10 - 15 = 3 дня

Попытка создать заявку на 5 дней:
❌ Недостаточно дней (доступно 3, запрошено 5)
```

#### 2. Одобрение HR

```
При одобрении:
├── Статус → approved
├── Дни вычитаются из баланса
├── annual_days_used += days_count (для annual)
├── dayoff_days_used += days_count (для dayoff)
└── Сотрудник получает уведомление
```

#### 3. Отклонение

```
При отклонении:
├── Статус → rejected_hr
├── Дни НЕ вычитаются
├── Баланс не изменяется
└── Сотрудник получает уведомление с причиной
```

#### 4. Отмена заявки

```
Сотрудник может отменить:
├── Только заявки в статусе pending_*
├── Дни возвращаются в "доступные"
└── Можно создать новую заявку

Нельзя отменить:
├── Одобренные заявки (approved)
└── Отклоненные заявки (rejected_*)
```

### Отображение баланса

**На странице заявки:**
```
Ежегодный оплачиваемый
├── Большая цифра: Доступно дней
├── Маленькая: из X дней
└── Если есть ожидающие: (Y дн. в ожидающих заявках)
```

**Цветовая индикация:**
- Зеленый: > 50% дней доступно
- Желтый: 20-50% дней доступно
- Красный: < 20% дней доступно
- Серый: 0 дней (заблокировано)

### Управление балансами

**Просмотр балансов:**
```sql
SELECT 
    u.username,
    u.firstname,
    u.lastname,
    v.annual_days_total,
    v.annual_days_used,
    v.annual_days_total - v.annual_days_used as annual_remaining,
    v.dayoff_days_total,
    v.dayoff_days_used,
    v.dayoff_days_total - v.dayoff_days_used as dayoff_remaining
FROM user_vacation_balance v
JOIN users u ON v.user_id = u.id
WHERE v.year = 2026;
```

**Сброс баланса (начало года):**
```sql
UPDATE user_vacation_balance
SET annual_days_used = 0,
    dayoff_days_used = 0
WHERE year = 2026;
```

**Изменение лимита для конкретного сотрудника:**
```sql
UPDATE user_vacation_balance
SET annual_days_total = 35
WHERE user_id = 123 AND year = 2026;
```

### Рекомендации

1. **Планирование лимитов**
   - Стандарт РФ: 28 дней
   - Можно увеличить для мотивации
   - Day Off: 3-5 дней оптимально

2. **Начало года**
   - Сбросьте использованные дни
   - Проверьте актуальность лимитов
   - Уведомите сотрудников о балансе

3. **Мониторинг**
   - Следите за использованием дней
   - Напоминайте о неиспользованных днях
   - Планируйте перенос на следующий год

4. **Исключения**
   - Индивидуальные лимиты через SQL
   - Дополнительные дни за выслугу лет
   - Компенсация за переработки

## Настройка карточки пользователя

**Путь:** Админ-панель → Система → LDAP → Конструктор карточки  
**Требуемое право:** `all` (только администратор)

### Обзор

Настройка отображения полей в карточке сотрудника в справочнике.

### Доступные поля

```
Контактная информация
├── Email
├── Телефон
├── Внутренний телефон
└── Местоположение

Рабочая информация
├── Отдел
├── Должность
├── Руководитель
└── Дата приема

Личная информация
├── День рождения
└── Дополнительные поля (кастомные)
```

### Настройка поля

Для каждого поля можно настроить:

```
Отображаемое название
└── Как поле называется в карточке

Иконка
├── Тип: FontAwesome, SVG, изображение
├── Значение: fa-envelope, fa-phone, и т.д.
└── Цвет: blue, green, purple, amber, и т.д.

Видимость
├── Показывать - поле отображается
└── Скрыть - поле не отображается

Ссылка
├── Является ли поле ссылкой
├── Префикс: mailto:, tel:, https://
└── Например: mailto:user@company.com

Секция
├── contact - Контакты
├── info - Информация
└── additional - Дополнительно

Порядок
└── Позиция в списке (можно перетаскивать)
```

### Пример настройки

**Email:**
```
Название: Email
Иконка: FontAwesome, fa-envelope
Цвет: blue
Ссылка: Да, mailto:
Секция: contact
Порядок: 1
```

**Телефон:**
```
Название: Телефон
Иконка: FontAwesome, fa-phone
Цвет: green
Ссылка: Да, tel:
Секция: contact
Порядок: 2
```

### Кастомные поля

Можно добавить дополнительные поля через LDAP маппинг:

1. Перейдите в **LDAP → Кастомные атрибуты**
2. Добавьте маппинг LDAP атрибута
3. Поле появится в конструкторе карточки
4. Настройте отображение

**Пример:**
```
LDAP атрибут: physicalDeliveryOfficeName
Поле портала: office_location
Название: Офис
Иконка: fa-building
```
