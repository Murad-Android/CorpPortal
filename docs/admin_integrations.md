## LDAP / Active Directory

**Путь:** Админ-панель → Система → LDAP  
**Требуемое право:** `settings_ldap`

### Обзор

Интеграция с корпоративным Active Directory для:
- Автоматической синхронизации пользователей
- Единого входа (SSO)
- Автоматического обновления данных сотрудников
- Маппинга групп AD на роли портала

### Базовые настройки

```
Включить LDAP
└── Переключатель вкл/выкл

Сервер LDAP*
├── IP адрес или hostname
├── Например: dc.company.local
└── Или: 192.168.1.10

Порт*
├── 389 - стандартный LDAP
├── 636 - LDAPS (с SSL)
└── 3268 - Global Catalog

Использовать SSL
├── Да - защищенное соединение (LDAPS)
└── Нет - обычное соединение

Домен*
├── Домен Active Directory
└── Например: COMPANY или company.local

Base DN*
├── Базовый DN для поиска
└── Например: DC=company,DC=local
```

### Учетная запись для подключения

```
Bind User*
├── Пользователь для подключения к AD
├── Формат: CN=ldapuser,OU=Service,DC=company,DC=local
└── Или: ldapuser@company.local

Bind Password*
├── Пароль учетной записи
└── Хранится в зашифрованном виде

Фильтр пользователей
├── LDAP фильтр для поиска пользователей
├── По умолчанию: (sAMAccountName={username})
└── Можно изменить для специфичных требований
```

### Маппинг атрибутов

Соответствие между атрибутами AD и полями портала:

```
Стандартные атрибуты:

Имя (givenName)
└── Атрибут AD → Поле портала: firstname

Фамилия (sn)
└── Атрибут AD → Поле портала: lastname

Email (mail)
└── Атрибут AD → Поле портала: email

Телефон (telephoneNumber)
└── Атрибут AD → Поле портала: phone

Отдел (department)
└── Атрибут AD → Поле портала: department

Должность (title)
└── Атрибут AD → Поле портала: position

Руководитель (manager)
└── Атрибут AD → Поле портала: manager_id
```

### Кастомные атрибуты

Добавление дополнительных полей:

1. **Добавление атрибута**
   - Нажмите **"Добавить атрибут"**
   - Заполните поля:
     ```
     LDAP атрибут*
     └── Название атрибута в AD (например: physicalDeliveryOfficeName)

     Поле портала*
     └── Название поля в базе (например: office_location)

     Отображаемое название
     └── Название для пользователей (например: Офис)

     Активен
     └── Использовать при синхронизации
     ```

2. **Примеры кастомных атрибутов**
   ```
   physicalDeliveryOfficeName → office_location (Офис)
   employeeNumber → employee_id (Табельный номер)
   mobile → mobile_phone (Мобильный)
   company → company_name (Компания)
   ```

### Маппинг групп AD на роли

Автоматическое назначение ролей на основе членства в группах AD:

1. **Добавление маппинга**
   - Нажмите **"Добавить группу"**
   - Заполните поля:
     ```
     DN группы*
     └── Полный DN группы в AD
     └── Например: CN=Portal_Admins,OU=Groups,DC=company,DC=local

     Название группы
     └── Понятное название (опционально)
     └── Например: Администраторы портала

     Роль портала*
     └── Выбор роли из списка
     └── Например: admin, hr, secretary
     ```

2. **Примеры маппинга**
   ```
   CN=Portal_Admins,OU=Groups,DC=company,DC=local
   └── Роль: admin

   CN=HR_Department,OU=Groups,DC=company,DC=local
   └── Роль: hr

   CN=Office_Managers,OU=Groups,DC=company,DC=local
   └── Роль: secretary
   ```

3. **Логика назначения**
   - При синхронизации проверяется членство в группах
   - Если пользователь в группе - назначается соответствующая роль
   - Если в нескольких группах - назначается роль с наибольшими правами
   - Если не в группах - назначается роль "user" по умолчанию

### Синхронизация пользователей

#### Ручная синхронизация

1. Нажмите **"Синхронизировать сейчас"**
2. Дождитесь завершения процесса
3. Просмотрите результаты:
   ```
   Найдено пользователей в AD: X
   Создано новых: Y
   Обновлено существующих: Z
   Ошибок: N
   ```

#### Автоматическая синхронизация

Настройка через cron (Linux) или Task Scheduler (Windows):

```bash
# Каждый день в 3:00
0 3 * * * cd /path/to/portal && venv/bin/python sync_ldap.py

# Каждые 6 часов
0 */6 * * * cd /path/to/portal && venv/bin/python sync_ldap.py
```

#### Что синхронизируется

```
Создание пользователей:
├── Новые пользователи из AD создаются на портале
├── Генерируется случайный пароль (не используется при LDAP auth)
├── Назначается роль на основе групп
└── Заполняются все маппированные поля

Обновление пользователей:
├── Обновляются все маппированные атрибуты
├── Обновляется роль на основе групп
├── НЕ обновляется пароль
└── НЕ обновляются поля, измененные вручную (опционально)

Деактивация пользователей:
├── Пользователи, удаленные из AD, деактивируются
├── Данные сохраняются
└── Можно настроить автоудаление
```

### Фильтрация синхронизации

Синхронизация только определенной группы:

```
DN группы для синхронизации
├── Если указан - синхронизируются только члены группы
├── Если пусто - синхронизируются все пользователи
└── Например: CN=Portal_Users,OU=Groups,DC=company,DC=local

Пример использования:
├── Создайте группу "Portal_Users" в AD
├── Добавьте в нее сотрудников, которым нужен доступ
├── Укажите DN группы в настройках
└── При синхронизации создадутся только эти пользователи
```

### Аутентификация через LDAP

При включенном LDAP:

1. **Вход пользователя**
   ```
   Пользователь вводит логин и пароль
   ↓
   Система проверяет, является ли пользователь LDAP
   ↓
   Если да - проверка пароля в AD
   ↓
   Если нет - проверка локального пароля
   ↓
   Успешный вход
   ```

2. **Преимущества**
   - Единый пароль для всех систем
   - Автоматическая блокировка при увольнении
   - Соответствие политикам безопасности AD
   - Не нужно помнить отдельный пароль

3. **Локальные пользователи**
   - Пользователи, созданные вручную, остаются локальными
   - Используют локальный пароль
   - Не синхронизируются с AD
   - Можно преобразовать в LDAP пользователя

### Устранение неполадок

#### Ошибка подключения

```
Проверьте:
├── Доступность сервера (ping dc.company.local)
├── Открыт ли порт (telnet dc.company.local 389)
├── Правильность учетных данных
└── Firewall не блокирует соединение
```

#### Пользователи не синхронизируются

```
Проверьте:
├── Base DN указан правильно
├── Bind User имеет права на чтение
├── Фильтр пользователей корректен
├── Группа для синхронизации существует
└── Логи синхронизации (см. раздел Логи)
```

#### Роли не назначаются

```
Проверьте:
├── DN групп указаны правильно (полный путь)
├── Пользователи действительно в этих группах
├── Роли существуют на портале
└── Маппинг групп сохранен
```

#### Атрибуты не обновляются

```
Проверьте:
├── Атрибуты существуют в AD
├── Bind User имеет права на чтение атрибутов
├── Маппинг атрибутов активен
└── Атрибуты не пустые в AD
```

### Тестирование подключения

1. Нажмите **"Тестировать подключение"**
2. Система проверит:
   ```
   ✓ Подключение к серверу
   ✓ Аутентификация Bind User
   ✓ Доступность Base DN
   ✓ Поиск тестового пользователя
   ```
3. Результат отобразится на экране

## SMTP / Email

**Путь:** Админ-панель → Система → SMTP  
**Требуемое право:** `settings_smtp`

### Обзор

Настройка почтового сервера для отправки уведомлений пользователям.

### Настройки SMTP

```
Включить SMTP
└── Переключатель вкл/выкл

SMTP Сервер*
├── Адрес почтового сервера
├── Например: smtp.gmail.com
└── Или: mail.company.com

Порт*
├── 25 - стандартный SMTP
├── 587 - SMTP с TLS (рекомендуется)
├── 465 - SMTP с SSL
└── 2525 - альтернативный порт

Использовать TLS
├── Да - STARTTLS (порт 587)
└── Нет - без шифрования

Использовать SSL
├── Да - SSL/TLS (порт 465)
└── Нет - без SSL

Имя пользователя*
├── Email или логин для SMTP
└── Например: noreply@company.com

Пароль*
├── Пароль от почтового ящика
└── Хранится в зашифрованном виде

Email отправителя*
├── От кого приходят письма
└── Например: noreply@company.com

Имя отправителя
├── Отображаемое имя
└── Например: Корпоративный портал
```

### Примеры настроек

#### Gmail

```
Сервер: smtp.gmail.com
Порт: 587
TLS: Да
SSL: Нет
Пользователь: your-email@gmail.com
Пароль: app-specific password (не обычный пароль!)

Примечание: Нужно создать пароль приложения в настройках Google
```

#### Yandex

```
Сервер: smtp.yandex.ru
Порт: 587
TLS: Да
SSL: Нет
Пользователь: your-email@yandex.ru
Пароль: пароль от почты
```

#### Mail.ru

```
Сервер: smtp.mail.ru
Порт: 587
TLS: Да
SSL: Нет
Пользователь: your-email@mail.ru
Пароль: пароль от почты
```

#### Корпоративный Exchange

```
Сервер: mail.company.com
Порт: 587
TLS: Да
SSL: Нет
Пользователь: noreply@company.com
Пароль: пароль учетной записи
```

### Тестирование

1. Заполните настройки SMTP
2. Введите тестовый email
3. Нажмите **"Отправить тестовое письмо"**
4. Проверьте почту (включая спам)

**Если письмо не пришло:**
```
Проверьте:
├── Правильность настроек
├── Доступность SMTP сервера
├── Правильность учетных данных
├── Firewall не блокирует порт
└── Email не попал в спам
```

### Типы уведомлений

При включенном SMTP отправляются:

```
Пользователям:
├── Создание учетной записи (логин и пароль)
├── Сброс пароля
├── Новая заявка (статус изменен)
├── Новый комментарий к новости
├── Приглашение на опрос/тест
└── Напоминания о событиях

Администраторам:
├── Новая заявка на обработку
├── Новый отклик на вакансию
├── Ошибки системы
└── Отчеты по расписанию

Руководителям:
├── Заявка на отпуск от подчиненного
├── Новый подчиненный
└── Напоминания о необработанных заявках
```

### Шаблоны писем

Шаблоны находятся в `app/templates/emails/`:

```
welcome.html - Приветственное письмо
password_reset.html - Сброс пароля
vacation_request.html - Заявка на отпуск
pass_request.html - Заявка на пропуск
order_request.html - Заявка на заказ
survey_invitation.html - Приглашение на опрос
test_reminder.html - Напоминание о тесте
```

Можно кастомизировать шаблоны под свой бренд.

## Мониторинг и логи

**Путь:** Админ-панель → Система → Логи  
**Требуемое право:** `logs_view`

### Журнал аудита

Фиксирует все важные действия в системе:

```
Действия пользователей:
├── Вход/выход из системы
├── Изменение пароля
├── Изменение профиля
└── Создание/изменение контента

Административные действия:
├── Создание/изменение пользователей
├── Изменение ролей и прав
├── Изменение настроек системы
├── Обработка заявок
└── Синхронизация LDAP

Системные события:
├── Ошибки приложения
├── Ошибки подключения к БД
├── Ошибки SMTP
└── Ошибки LDAP
```

### Просмотр логов

**Фильтры:**
- По дате (от - до)
- По пользователю
- По типу действия
- По сущности (пользователь, новость, заявка и т.д.)

**Информация в записи:**
```
Дата и время
Пользователь (кто совершил действие)
Действие (что сделано)
Тип сущности (с чем работали)
ID сущности
Детали (дополнительная информация)
IP адрес
```

### Экспорт логов

- Excel - для анализа
- CSV - для импорта в другие системы
- JSON - для автоматической обработки

### Хранение логов

```
База данных:
├── Таблица: audit_logs
├── Хранение: 90 дней (по умолчанию)
└── Автоматическая очистка старых записей

Файловые логи:
├── Путь: logs/app.log
├── Ротация: ежедневно
├── Хранение: 30 дней
└── Формат: текстовый
```

### Мониторинг системы

**Метрики на главной странице:**
- Количество активных пользователей
- Количество заявок в обработке
- Использование дискового пространства
- Последние ошибки

**Рекомендации:**
- Регулярно проверяйте логи на ошибки
- Настройте уведомления о критических ошибках
- Экспортируйте логи для долгосрочного хранения
- Анализируйте действия администраторов
