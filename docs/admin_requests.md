## Заявки на пропуска

**Путь:** Админ-панель → Заявки → Пропуска  
**Требуемое право:** `passes`

### Обзор

Система управления заявками на оформление пропусков для посетителей.

### Информация в заявке

```
Данные посетителя
├── ФИО посетителя*
├── Компания
├── Документ (паспорт, водительское удостоверение)
└── Контактный телефон

Данные визита
├── Дата визита*
├── Дата окончания (для многодневных пропусков)
├── Цель визита
└── Принимающий сотрудник*

Статус заявки
├── Ожидает обработки (pending)
├── Одобрено (approved)
└── Отклонено (rejected)

Служебная информация
├── Кто подал заявку
├── Дата создания
├── Кто обработал
├── Дата обработки
└── Комментарий обработчика
```

### Обработка заявки

1. **Просмотр заявки**
   - Откройте список заявок
   - Нажмите на заявку для просмотра деталей

2. **Одобрение**
   - Проверьте данные посетителя
   - Убедитесь в корректности дат
   - Нажмите **"Одобрить"**
   - Добавьте комментарий (опционально)
   - Подтвердите действие

3. **Отклонение**
   - Нажмите **"Отклонить"**
   - **Обязательно** укажите причину отклонения
   - Подтвердите действие

### Уведомления

- Подавший заявку получает уведомление о статусе
- Принимающий сотрудник получает уведомление об одобрении
- Служба безопасности получает список одобренных пропусков

### Экспорт

**Форматы:**
- Excel - список пропусков за период
- PDF - пропуск для печати
- CSV - для импорта в систему СКУД

**Фильтры:**
- По дате визита
- По статусу
- По принимающему сотруднику
- По компании посетителя

## Заявки на заказ товаров

**Путь:** Админ-панель → Заявки → Заказы товаров  
**Требуемое право:** `orders`

### Обзор

Система управления заявками на заказ канцелярии, оборудования и других товаров.

### Информация в заявке

```
Данные заказа
├── Отдел*
├── Название товара*
├── Артикул/модель
├── Количество*
├── Приоритет (обычный, срочный, очень срочный)
└── Примечания

Статус заявки
├── Ожидает обработки (pending)
├── В работе (processing)
├── Заказано (ordered)
├── Получено (received)
└── Отклонено (rejected)

Служебная информация
├── Кто подал заявку*
├── Дата создания
├── Кто обработал
├── Дата обработки
└── Комментарий обработчика
```

### Обработка заявки

1. **Просмотр и оценка**
   - Проверьте обоснованность заказа
   - Уточните детали у заявителя (если нужно)
   - Проверьте наличие на складе

2. **Изменение статуса**
   ```
   Ожидает → В работе
   └── Заявка принята к обработке

   В работе → Заказано
   └── Товар заказан у поставщика

   Заказано → Получено
   └── Товар получен и передан заявителю

   Любой → Отклонено
   └── Заявка отклонена (с указанием причины)
   ```

3. **Комментарии**
   - Добавляйте комментарии на каждом этапе
   - Указывайте сроки поставки
   - Фиксируйте номер заказа у поставщика

### Приоритеты

```
Обычный (normal)
└── Стандартная обработка, 5-7 дней

Срочный (urgent)
└── Ускоренная обработка, 1-2 дня

Очень срочный (critical)
└── Немедленная обработка, в тот же день
```

### Отчеты

**Доступные отчеты:**
- Заявки по отделам
- Самые заказываемые товары
- Статистика по срокам обработки
- Бюджет по отделам (если указаны цены)

## Система отпусков

**Путь:** Админ-панель → Заявки → Отпуска  
**Требуемое право:** `vacations`

### Обзор

Комплексная система управления отпусками сотрудников с автоматическим учетом лимитов.

### Вкладки

#### 1. Ожидают HR

Заявки, одобренные руководителями и ожидающие решения HR.

**Информация:**
- ФИО сотрудника
- Даты отпуска (начало - окончание)
- Количество дней
- Тип отпуска
- Комментарий сотрудника
- Комментарий руководителя
- Дата подачи заявки

**Действия:**
- Одобрить (дни автоматически вычитаются из баланса)
- Отклонить (с указанием причины)

#### 2. Все заявки

Полная история заявок с фильтрами.

**Фильтры:**
- По статусу (все, ожидают, одобрены, отклонены)
- По отделу
- По типу отпуска
- По периоду

**Статусы:**
```
pending_manager
└── Ожидает одобрения руководителя

pending_hr
└── Ожидает одобрения HR

approved
└── Одобрено (дни вычтены из баланса)

rejected_manager
└── Отклонено руководителем

rejected_hr
└── Отклонено HR
```

#### 3. Правила конфликтов

Настройка ограничений на одновременные отпуска.

**Назначение:**
Предотвращение ситуаций, когда критически важные сотрудники уходят в отпуск одновременно.

**Создание правила:**
1. Выберите первого сотрудника
2. Выберите второго сотрудника
3. Укажите причину (опционально)
4. Сохраните

**Пример:**
```
Сотрудник A: Главный бухгалтер
Сотрудник B: Заместитель главного бухгалтера
Причина: Должен быть хотя бы один бухгалтер в офисе
```

**Действие правила:**
- При подаче заявки система проверяет конфликты
- Если даты пересекаются - заявка блокируется
- Сотрудник видит сообщение о конфликте
- Нужно выбрать другие даты

### Типы отпусков

```
annual (Ежегодный оплачиваемый)
├── Ограничен лимитом (по умолчанию 28 дней)
├── Дни вычитаются при одобрении HR
├── Учитываются ожидающие заявки
└── Блокируется при исчерпании лимита

dayoff (Day Off)
├── Дополнительные выходные дни
├── Включается в настройках
├── Настраиваемый лимит
└── Отдельный учет от ежегодного отпуска

unpaid (За свой счёт)
├── Неоплачиваемый отпуск
├── Не ограничен лимитом
└── Всегда доступен
```

### Обработка заявки HR

1. **Проверка заявки**
   - Убедитесь, что руководитель одобрил
   - Проверьте баланс дней сотрудника
   - Проверьте отсутствие конфликтов
   - Проверьте производственную необходимость

2. **Одобрение**
   - Нажмите **"Одобрить"**
   - Добавьте комментарий (опционально)
   - Подтвердите действие
   - **Дни автоматически вычитаются из баланса**

3. **Отклонение**
   - Нажмите **"Отклонить"**
   - **Обязательно** укажите причину
   - Подтвердите действие
   - Дни остаются в балансе

### Баланс отпускных дней

**Как работает:**

1. **Инициализация**
   - При первой заявке создается баланс
   - Берутся значения из настроек системы
   - Привязывается к году

2. **Учет дней**
   ```
   Всего дней = Настройка системы (28)
   Использовано = Одобренные заявки
   В ожидании = Заявки pending_manager + pending_hr
   Доступно = Всего - Использовано - В ожидании
   ```

3. **Проверка при создании заявки**
   - Система проверяет доступный баланс
   - Учитывает ожидающие заявки
   - Блокирует создание если дней недостаточно

4. **Вычитание дней**
   - Происходит только при одобрении HR
   - Автоматически обновляется баланс
   - Сотрудник видит обновленный баланс

### Настройка лимитов

**Путь:** Админ-панель → Система → Отпуска

См. подробнее в [Настройки системы - Отпуска](README_ADMIN_SETTINGS.md#настройки-отпусков)

### Отчеты и аналитика

**Доступные отчеты:**
- График отпусков по отделам
- Использование отпускных дней
- Сотрудники с неиспользованными днями
- Статистика одобрений/отклонений
- Средний срок обработки заявок

**Экспорт:**
- Excel - полный отчет с графиками
- PDF - график отпусков для печати
- iCal - импорт в календарь

### Уведомления

**Сотрудник получает уведомления:**
- Заявка отправлена руководителю
- Руководитель одобрил/отклонил
- HR одобрил/отклонил
- Приближается дата отпуска (за 3 дня)

**Руководитель получает уведомления:**
- Новая заявка от подчиненного
- Напоминание о необработанных заявках

**HR получает уведомления:**
- Заявка одобрена руководителем
- Напоминание о необработанных заявках

### Рекомендации

1. **Своевременная обработка**
   - Обрабатывайте заявки в течение 1-2 дней
   - Не откладывайте решение на последний момент
   - Используйте уведомления

2. **Планирование**
   - Следите за графиком отпусков отдела
   - Предотвращайте массовые отпуска
   - Используйте правила конфликтов

3. **Коммуникация**
   - Всегда указывайте причину отклонения
   - Добавляйте комментарии при одобрении
   - Связывайтесь с сотрудником при вопросах

4. **Контроль лимитов**
   - Регулярно проверяйте балансы сотрудников
   - Напоминайте об неиспользованных днях
   - Планируйте перенос дней на следующий год
